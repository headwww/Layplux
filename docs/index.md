## IntelliJ IDEA 风格 ToolWindow 布局系统详解

### 一、整体框架

IDE 界面分为五个区域：顶部、底部、左侧、右侧、中心编辑区。

顶部和底部均为交互性或提示性组件，通过点击触发，不承载工具面板。

左右两侧为 ToolWindowStripe（工具窗口条），是承载工具面板入口的专属区域。每个注册进来的插件在 Stripe 上对应一个图标，点击图标控制其面板的打开与关闭。

---

### 二、六大区域划分

左右两侧的 Stripe 各自划分三个区域，合计六个：


| 位置   | 说明                            |
| ---- | ----------------------------- |
| 左侧顶部 | 左侧 Stripe 上半部分的上区域            |
| 左侧底部 | 左侧 Stripe 上半部分的下区域，两区域之间以横线分隔 |
| 底部左侧 | 左侧 Stripe 下半部分，触发底部弹出面板       |
| 右侧顶部 | 右侧 Stripe 上半部分的上区域            |
| 右侧底部 | 右侧 Stripe 上半部分的下区域            |
| 底部右侧 | 右侧 Stripe 下半部分，触发底部弹出面板       |


左侧上半部分额外有一个 More 图标，当 Stripe 图标过多放不下时，溢出的插件折叠进 More 菜单，也可以从 More 菜单里把插件拖回 Stripe。右侧没有 More 图标。

---

### 三、插件与面板的对应关系

每个注册进来的插件对应一个全局唯一的面板实例，该实例在应用启动后永远不销毁。面板的所有行为（打开、关闭、切换区域、切换停靠模式）都是对这个实例状态的修改，不涉及组件的创建和销毁。

同一个区域内可以存在多个插件，但同一时刻只能有一个插件的面板处于激活显示状态，其余面板隐藏但保留完整状态。切换激活面板时，隐藏的面板内容（输入、滚动位置、数据等）全部保留，再次激活时恢复如初。

面板在第一次被打开之前不创建任何 DOM，第一次打开后 DOM 永远保留，后续的关闭和隐藏只改变其显示状态，不销毁结构。

---

### 四、三种停靠模式

每个面板支持三种停靠模式，模式之间可以随时切换，切换不会销毁面板内容：

**停靠固定（Docked Pinned）**
面板固定展开并挤压中心编辑区。若左侧两个区域同时处于停靠固定状态，则两个面板上下各占左侧一半高度。

**停靠不固定（Docked Unpinned）**
面板展开时同样挤压中心编辑区，但当面板失去焦点时自动收起，恢复编辑区空间。

**浮动（Float）**
面板以浮动形式覆盖在中心区域之上，不影响编辑区布局。失去焦点时自动收起。浮动面板的层级高于所有停靠类型的面板。由于浮动面板失去焦点即收起，同一时刻最多只存在一个浮动面板。

---

### 五、底部弹出面板

底部左侧和底部右侧触发的面板从底部向上弹出，会同时挤压左侧面板区域、右侧面板区域以及中心编辑区。若当前存在浮动面板，底部面板层级低于浮动面板，不产生冲突。

---

### 六、面板尺寸

停靠固定和停靠不固定的面板，其边缘可以拖拽调整宽度（左右面板）或高度（底部面板），调整后的尺寸持久保存。浮动面板同样支持拖拽调整尺寸，并且可以拖动改变其在工作区中的位置。

---

### 七、区域间拖拽

左右两侧 Stripe 上的插件图标可以在六个区域之间自由拖拽移动。

拖拽完成后，该插件的面板内容渲染在新区域对应的位置，面板内容不会因区域切换而销毁重建，组件内部的所有状态完整保留。

拖拽前面板处于打开状态，切换后仍然打开并显示在新位置；拖拽前面板处于关闭状态，切换后仍然保持关闭。

---

### 八、面板层级关系

从低到高依次为：停靠固定面板 → 停靠不固定面板 → 底部弹出面板 → 浮动面板。浮动面板始终处于最顶层，覆盖其他所有类型的面板。

## Widget、Pane、Area 对象关系说明

---

### skeleton

所有对象的起点，负责初始化整个系统。创建所有 area、六个 pane 实例，以及管理所有注册进来的 widget。

---

### area

管理 pane 实例，分为上下左右四个方向。上下 area 装载交互型 widget，左右 area 装载面板型 widget，同时左右 area 也持有对应 pane 的引用。

---

### widget

注册进系统的最小单元，分为两种性质：

**交互型 widget**，停靠在上下 area，点击直接触发行为，不持有 pane-runtime，不控制面板。

**面板型 widget**，停靠在左右 area，持有两样东西：一是自己的 pane-runtime 状态机，二是面板内容组件的引用。点击时触发自身 pane-runtime 的状态变化，从而控制面板的显示行为。

---

### pane-runtime

归属于面板型 widget，是控制面板行为的状态机，记录以下状态：

- 当前停靠模式（停靠固定、停靠不固定、浮动）
- 面板是否打开
- 是否已经挂载过（懒挂载标志）
- 面板尺寸（宽度、高度）
- 浮动时的位置（x、y）
- 当前所在的 pane 区域

widget 携带自己的 pane-runtime 在不同 pane 之间移动，pane-runtime 的状态不因移动而重置。

---

### pane

一共六个实例，对应六个区域（左侧顶部、左侧底部、底部左侧、右侧顶部、右侧底部、底部右侧），由 area 管理。

pane 是被动容器，本身不感知 pane-runtime 的存在，只记录当前激活的 widget id。同一个 pane 内可以有多个 widget，但同一时刻只有一个处于激活显示状态，其余 widget 的面板内容隐藏但不销毁。

pane 不主动传递任何状态，拖拽换区域时是 widget 携带自己的 pane-runtime 主动移动到目标 pane，pane 被动接收。

---

### 对象关系总览

```
skeleton
  ├── area × 4（上、下、左、右）
  │     ├── 上下 area → 装载交互型 widget
  │     └── 左右 area → 装载面板型 widget，持有 pane 引用
  │
  ├── pane × 6（被动容器，记录当前激活的 widget id）
  │
  └── widget × N
        ├── 交互型：点击触发行为，无 pane-runtime
        └── 面板型：持有 pane-runtime + 面板内容组件引用
              └── pane-runtime（状态机：模式、开关、尺寸、位置、所在区域）
```

**拖拽前的状态**

```
pane-left-top 容器：visible，宽度 280px，挤压中心区域
  └── widget-A 的面板内容 DOM：v-show=true

pane-right-top 容器：hidden，宽度 0
  └── 空

```

---

**拖拽过程中（鼠标还没松开）**

没有任何状态变化，只是拖拽图标的视觉反馈，所有面板保持原样。

---

**拖拽松开后，按顺序发生**

```
第一步：widget-A 归属从 area-left-top 改为 area-right-top

第二步：pane-left-top 的 activeId 清空
        → 容器宽度变为 0，视觉上左侧面板收起

第三步：Teleport 的 to 目标从 #pane-left-top 改为 #pane-right-top
        → 面板内容 DOM 被移动到右侧容器，组件实例不动

第四步：pane-right-top 的 activeId 设为 widget-A，isOpen=true
        → 容器宽度变为 280px，视觉上右侧面板展开


```

---

**拖拽后的状态**

```
pane-left-top 容器：hidden，宽度 0
  └── 空

pane-right-top 容器：visible，宽度 280px，挤压中心区域
  └── widget-A 的面板内容 DOM：v-show=true，状态完整保留

```

---

**视觉上的感受**

左侧面板瞬间收起，右侧面板瞬间展开，中心编辑区先被左侧释放的空间补充，再被右侧挤压回去。如果加上 CSS transition 对宽度做动画，这个过程会显得很流畅自然。
